# ANTS 迭代3 优化后效果展望（管理端 / 用户 / 司机 三视角）

| 项 | 内容 |
|---|---|
| 版本 | 迭代3 效果展望（配套《迭代3-体验优化方向（修订版）》） |
| 状态 | 待评审 |
| 口径 | "现在"均为代码体检事实；"优化后"为迭代3 落地后的目标效果，数字为**目标值/估测，非实测** |

> 阅读方式：分别从**管理端（平台运营）**、**用户（客户/货主）**、**司机（车队/个人/子账号）**三个视角看"做完之后是什么样、得到什么"。价格模式不变、Zalo 与 P2 暂缓的边界同样适用。

---

## 一、管理端（平台运营）视角

| 现在（代码事实） | 优化后 | 收益 |
|---|---|---|
| 流标、超时自动审核、协商过期**依赖用户打开页面才发生**（`sweepDeadlines()` 仅在 API 调用时触发，无定时任务） | 定时任务每 1 分钟兜底，到点自动流标/自动通过/协商过期 | **0 人工盯盘**，纸面规则变成真实行为；订单不再"卡死在匹配中" |
| 5km 圆撮合，运营无法解释"为什么推这单给这车" | 顺路度打分，每单有打分明细（装货点距离/目的顺路/时间窗/车型吨位），权重可配 | 撮合**可解释、可调参**，异常推荐能定位原因 |
| 订单热度无人可见 | 每单显示「已推送 X 位顺路司机 · 正在被 Y 位查看」，冷热一目了然 | **冷单 T+0 发现**，运营可提前介入（建议改价/电话协调），而不是等流标后救火 |
| 车辆异常只有一个状态标签，无信息 | 异常结构化上报（原因分类 + 照片 + 预计延迟） | 异常**可批量看、处理快、可追责**，客户争议有据 |
| 站内通知司机看不到（司机在 Zalo/电话上） | 司机端横幅 + 浏览器通知 + 安卓壳本地通知（Zalo 后续） | 运营发的消息**司机真收得到**，催单/协调有效 |
| 代客建单、注册审核、子账号体系完整 | 全部保留，只改手感 | 存量功能零破坏 |

管理端效果小结（目标）：**从"人盯状态、规则看运气"变为"自动兜底 + 撮合可解释 + 冷单可见 + 消息可达"**，运营时间从盯盘转向处理真正需要人的事（审核、异常、商务）。

## 二、用户（客户/货主）视角

| 现在（代码事实） | 优化后 | 收益 |
|---|---|---|
| 越南地址全靠手打，易错；堆场码头 76% 无坐标、不带出省市区 | 街道输入出联想候选；选堆场码头自动带省/市/区与坐标 | **填单快、地址准**，脏数据减少，后续匹配变准 |
| 看不到这票货多远、要跑多久（全库无路线/距离计算） | 起终点填齐实时显示「约 X 公里 · 约 Y 小时」 | **"货多远"一眼可见**，填目标价有依据，不再心里没底 |
| 提交后进裸详情页，状态"匹配中"，无任何预期管理 | 引导卡片（路径/等待时长/可延长1次/流标可重发）+ 倒计时 + 「已推送 X 司机 · Y 在查看」 | **知道会发生什么**，减少焦虑和客服电话 |
| 撮合建议"相距约 X 公里"看不懂；双端确认可能永远卡死 | 显示「顺路度：高/中/低」+ 理由；撮合建议 30 分钟时效、到期自动失效、对方确认后催促 | **看得懂、不等死** |
| 8 页签 + 10 查询字段 + 1800px 宽表格，手机上没法用 | 首页 3 入口卡片流（进行中/待处理/历史），手机无横向滚动 | **现场也能操作**，90% 日常操作单手完成 |
| 流标/被拒后只有状态变化，不知怎么办 | 首页一键「改价重发」，预填原单只改价格/时间 | **自助挽回**，不再等运营 |

用户效果小结（目标）：建单填写时间 **-40% 左右**（分步化 + 联想）；"下一步该干嘛"类咨询显著下降；流标后自助重发，挽回率提升；成交前全程**看得见进展**。

## 三、司机（车队主账号 / 个人司机 / 子账号）视角

| 现在（代码事实） | 优化后 | 收益 |
|---|---|---|
| 订单中心宽表格 + 10 查询字段，手机上难用，无从判断哪单值得看 | **货源大厅卡片**：路线、里程/时长、价格、装货时间、倒计时一屏看完，**默认按顺路度排序** | **先看最值得看的单**，找货效率提升 |
| 新单没有任何提醒，不打开网页就错过 | 新单到达：页面横幅 / 浏览器通知 / 安卓壳本地通知（至少一种生效）；路径 A 新单 30~60 秒**接单窗口** | 锁屏也有提醒，**不错过好单** |
| 路径 A 列表里找单再点详情接单 | 卡片上直接「**抢单**」（对标运满满） | 抢单路径缩短 |
| 路径 B 报价全凭感觉，无里程依据 | 订单卡片显示里程/时长，出价有依据 | **报价更合理，成交率提升** |
| 发布运力后无下文，等客户来找 | 发布/编辑运力后自动收到**顺路货源推荐**进待处理列表并提醒；货源更新增量重算 | **主动找货**，空驶率下降 |
| 车辆异常 = 裸按钮，点了只有标签 | 异常上报表单（原因分类 + 照片 + 预计延迟） | 异常**表达清楚**，客户/运营看得懂 |
| 空态文案看不懂（"轨迹条上的订单会出现在这里"） | 空态全部改写为"下一步该干什么" | 打开就知道要干嘛 |
| 子账号规则：看不到价格、不能接出价单 | 规则不变，界面同款优化 | 权限边界不破，体验一致 |

司机效果小结（目标）：找货从"翻表"到"按顺路度看 Top 卡片"；新单触达从"打开网页才知道"到"锁屏也提醒"；报价、抢单都有依据和窗口；**司机从被动等撮合变为主动找货**。

## 四、三端一句话总结

| 视角 | 现在 | 优化后 |
|---|---|---|
| 管理端 | 人盯状态、规则看运气、司机收不到消息 | 定时任务自动兜底、撮合可解释、冷单 T+0 可见、消息真到达 |
| 用户 | 手打地址、不知道多远、下单后黑箱、手机用不了 | 地址联想 + 距离时长、过程透明带倒计时、手机卡片流、流标自助重发 |
| 司机 | 翻表格找货、错过新单、报价靠感觉 | 货源大厅顺路排序、新单强提醒 + 接单窗口、报价有依据、顺路货源推上门 |

## 五、效果怎么验证（上线前后对比指标）

| 视角 | 指标 | 期望方向 |
|---|---|---|
| 管理端 | 定时任务执行日志（流标/超时自动发生率） | 100% 自动，不再依赖访问 |
| 管理端 | 冷单从发布到首次人工介入时间 | 缩短（T+0 可见） |
| 用户 | 建单完成率 / 建单耗时 | 提升 / 下降 |
| 用户 | 发布 → 首次司机响应时间 | 缩短（司机主动找货） |
| 用户 | 流标率、"待确认报价"超时率 | 下降 |
| 用户 | "下一步怎么办"类客服咨询量 | 下降 |
| 司机 | 货源大厅使用率、抢单/报价响应时间 | 提升 / 缩短 |
| 司机 | 报价成交率 | 提升 |
| 司机 | 新单提醒触达率（横幅/通知点击） | 提升 |

以上指标在迭代3 上线前后各取一个月对比，用结果决定迭代4 的取舍（地图化、定价引擎、Zalo 触达是否立项）。
